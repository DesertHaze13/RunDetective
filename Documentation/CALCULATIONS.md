# Run Detective calculation rules

All distances are meters, time is seconds, speed is meters/second, and heart rate is beats/minute. An unavailable source produces an unavailable result, never zero.

- Workout pace: workout duration / distance × 1000 seconds per kilometer. The UI labels this **workout pace** because elapsed workout time may include pauses when moving time is unavailable.
- Aggregate pace: sum of eligible workout durations / sum of their distances × 1000. Running and walking pace are calculated separately. A workout with no positive distance cannot enter a pace denominator. This is a workload descriptor only; mixed sessions cannot produce a performance verdict from this number.
- Aggregate speed: summed distance / summed duration for eligible workouts. The displayed km/h value multiplies by 3.6. It is not used to claim that a week of mixed runs was faster.
- Average heart rate: sort the workout's HealthKit heart-rate samples by time. Give each reading the time until the next reading, capped at 30 seconds (the final reading gets 5 seconds). The workout average is the sum of reading × weight divided by sum of weights. Coverage is capped at workout duration. Across workouts, weight each valid workout average by its own coverage, not by total workout duration. Missing HR is excluded, not zero-filled. A gap longer than 30 seconds is not treated as measured coverage.
- Maximum heart rate: maximum observed heart-rate sample value across included workouts. It is unavailable when no samples exist.
- Daily/weekly totals: sum observed distance, duration, and energy. Missing individual values are excluded and the UI marks incomplete totals when relevant.
- Percentage change: (current − previous) / previous × 100. It is unavailable when previous is zero or missing. Absolute difference is current − previous.
- Pace change: previous pace − current pace, so a positive number means faster. For comparison, use the same workout type and prefer similar distances and durations.
- Today run-to-run cards: sort HealthKit running workouts by start time, newest first. By default compare item 0 with item 1, regardless of whether another historical run is more similar. The picker lists actual imported runs and only permits an earlier baseline. A default selection remains dynamic after each sync; a manual selection remains attached to the chosen HealthKit workout IDs. Every run metric card shows both recorded dates and its own measured or calculated values. A distance gap above 25% blocks a pace-performance verdict, even though the raw pace difference remains visible.
- Metric diamonds: arrows report the raw change in the card's named value: recent minus earlier. For pace, a downward arrow means fewer seconds per kilometer and therefore faster. For distance, energy, and HR, an upward arrow means a higher measured value, not automatically an improvement. `=` means change below the displayed threshold; `?` means a required value is missing. Analytical verdict diamonds are separate from these raw directions.
- Today weekly running cards: default to the current calendar week versus the preceding calendar week, including weeks without runs. A person can select two different weeks from the header. When the current week is selected, trim the baseline week to the same elapsed time since its start. This avoids comparing a partial week with a full week. Weekly totals describe distance, duration, frequency, and workload; per-run performance is shown on separate session cards with exact dates. A zero previous distance has no percentage change; say that the baseline is missing.
- Week-to-week session matching: show every run in the selected newer week separately. For each one, choose the earlier week's run with the smallest relative distance difference inside a 0.8–1.25 distance ratio. Do not use duration to choose the match because a faster time is what the comparison is testing. The same earlier run may be used by multiple newer runs when baseline sessions are scarce; disclose this and do not count the pairs as independent evidence. If no similar-distance baseline exists, show that run's observed values without comparison arrows or verdict.
- Card layout: each matched weekly run has a short evidence card followed by separate pace/speed, heart-rate, distance, and active-energy cards. The ordinary Today view also retains its latest-run, rolling seven-day, weekly volume, findings, walking, daily activity, and recent pace chart cards. Only the week performance cards use individual run pairs; weekly volume remains an aggregate workload measure.
- Faster-at-lower-HR goal: a single pair is an efficiency clue only when distance differs by at most 25%, pace improves by at least 5 sec/km, HR is at least 4 bpm lower, and both runs have HR sample coverage of at least 50% of workout duration. Similar pace with lower HR can also be a clue. Faster with higher HR is described as a possibly harder effort; slower with lower HR as a possibly easier effort. Missing HR or incomplete coverage blocks an efficiency verdict. Routes, elevation, pauses, weather, and intent remain caveats; no single pair proves fitness change.
- Live seven-day card: compare workouts starting in the trailing seven days with workouts starting in the preceding seven days. Both windows have equal duration and are recalculated after Health sync. A workout crossing a boundary belongs to the window containing its start time.
- Per-run speed: measured workout distance divided by recorded workout duration × 3.6 km/h. It is displayed beside that run's pace; neither value is averaged across runs for a performance verdict.
- Energy coverage: on comparison cards, display HealthKit active energy for each individual run and its matched earlier run. If either value is missing, show unavailable and no direction arrow. Daily totals may sum observed energy, but no aggregate energy total is used as a running performance verdict. Active energy is workload context, not a performance score.
- Training consistency: count distinct calendar days with running workouts in a completed week. Compare that count with the preceding week; do not imply a fitness gain from frequency alone.
- Volume caution: if prior running distance exceeds zero and completed-week running distance rises by more than 30%, flag the change as a workload increase rather than a diagnosis.
- Weekly confidence: **medium** when each compared week has at least two running sessions and every newer run has a similar-distance earlier match; **low** otherwise. No **high** label is issued without route and conditions data for the compared weeks.
- Route elevation gain: sum only positive altitude differences after filtering implausible jumps; without sufficiently reliable location altitude, elevation is unavailable.
- Split pace: elapsed time between interpolated route distance boundaries divided by split distance. A partial final split is labeled separately.
- Confidence: high requires at least three comparable sessions on each side, usable HR samples, and similar route/elevation; medium requires two comparable sessions and partial context; otherwise low. Missing GPS, HR, or very different distances lowers confidence.
- Comparable runs elsewhere in the app: same activity type, 0.8–1.25 distance ratio, 0.7–1.4 duration ratio, with elevation considered when available. The week-to-week session matcher above uses distance alone for candidate choice and then exposes duration/pace as outcomes.
- Personal records: use only observed workout distance/route split data for fastest 1K/5K/10K. A workout's average pace must not be extrapolated into a shorter-distance record.

Weekly boundaries use the user's current Calendar and locale. A partially completed current week is identified in the UI. No analysis makes a medical diagnosis.
